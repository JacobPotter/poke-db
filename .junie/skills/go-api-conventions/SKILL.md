# Go API Conventions Protocol

## Context
- **Module**: `github.com/JacobPotter/poke-db/api`
- **Runtime**: Go 1.23+
- **Frameworks**: Gin (web), GORM (ORM), Swaggo (Swagger docs), Testify (tests)
- **Database**: PostgreSQL 15+ (required for `NULLS NOT DISTINCT` indexes on evolution tables)

---

## Execution Steps

### 1. Controller Pattern — Constructor Injection

Controllers receive `*gorm.DB` via a constructor function, never via the global `models.DB`. This enables testing and keeps dependencies explicit.

```go
// controllers/pokemon.go
type PokemonHandler struct {
	db *gorm.DB
}

func NewPokemonHandler(db *gorm.DB) *PokemonHandler {
	return &PokemonHandler{db: db}
}
```

**When adding a new controller:**
- Create the handler struct with a `db *gorm.DB` field.
- Provide a `New<Name>Handler(db *gorm.DB) *<Name>Handler` constructor.
- Place the file in `../../../api/controllers`.
- Annotate handler methods with Swaggo comments (`@Summary`, `@Tags`, `@Param`, `@Success`, `@Router`).

### 2. Route Registration — Feature-Based

Each feature domain has its own package under `../../../api/routes` with a `RegisterRoutes` function:

```go
// routes/pokemonroutes/routes.go
func RegisterRoutes(router *gin.RouterGroup, db *gorm.DB) {
	handler := controllers.NewPokemonHandler(db)
	// Define routes
}
```

Routes are registered in `../../../api/routes/setup.go`:

```go
func SetupRouter(db *gorm.DB) *gin.Engine {
	router := gin.Default()
	v1 := router.Group("/api/v1")
	{
		pokemonroutes.RegisterRoutes(v1, db)
		typeroutes.RegisterRoutes(v1, db)
		evolutionroutes.RegisterRoutes(v1, db)
	}
	return router
}
```

**When adding a new feature domain:**
- Create `api/routes/<feature>routes/routes.go` with `RegisterRoutes(router *gin.RouterGroup, db *gorm.DB)`.
- Register it in `../../../api/routes/setup.go` inside the `/api/v1` group.
- Add the import to `setup.go`.

### 3. Migrations — Two-Tier Strategy

**Critical**: The API server and the refresh job use different migration scopes.

- `models.ConnectDatabase()` — called by the API server and tests. Only auto-migrates `coreModels()`:
  - `PokemonSpecies`, `Pokemon`, `MoveType`, `Item`, `Move`, `Location`, `Region`, `EvolutionTrigger`
- `models.MigrateAll(db)` — called by the refresh command. Migrates everything including:
  - `EvolutionChain`, `EvolutionChainLink`, `EvolutionDetails`

**Consequence**: A database started only by the API server will lack evolution tables. The refresh job or the SQL seed dump must run first.

**When adding a new model:**
- If the model is needed by the API server, add it to `coreModels()` in `../../../api/models/setup.go`.
- If the model is only populated by the refresh job, add it to `MigrateAll()` only.
- `EvolutionDetails` requires PostgreSQL 15+ for its `NULLS NOT DISTINCT` unique index.

### 4. Model Definitions

- Models live in `../../../api/models`.
- Use `GenericId` (uint alias) for primary keys that correspond to PokeAPI IDs.
- Use GORM tags for column names and relationships (`gorm:"foreignKey:..."`, `gorm:"constraint:..."`).
- For PostgreSQL array columns (e.g., damage type relationships), use `github.com/lib/pq` types (`pq.Int64Array`).
- Response structs (e.g., `ListPokemonResponse`) are also defined in `../../../api/models`.

### 5. Go 1.23 Language Idioms

Enforce these modern Go patterns in all new code:

| Use | Instead of |
|-----|------------|
| `any` | `interface{}` |
| `errors.Is(err, target)` | `err == target` |
| `slices.Contains(slice, item)` | manual loop |
| `slices.IndexFunc(slice, fn)` | manual loop |
| `maps.Clone(m)` / `maps.Keys(m)` | manual iteration |
| `for i := range n` | `for i := 0; i < n; i++` |
| `context.WithCancelCause` | `context.WithCancel` |
| `context.WithTimeoutCause` | `context.WithTimeout` |

### 6. Swagger Documentation & API Synchronization

- API-level annotations (`@BasePath`, `@title`, `@version`) live in `../../../api/main.go`.
- Handler-level annotations live in controller method comments (`@Summary`, `@Tags`, `@Param`, `@Success`, `@Failure`, `@Router`).
- `../../../api/docs` is generated by `swag init` — **do not hand-edit files in `docs/`**.
- After changing annotations or response models, regenerate: `cd api && swag init`.
- Swagger UI is served at `http://localhost:8080/swagger/index.html`.

### 7. Database & Schema Inspection via Postgres MCP

During backend development, leverage the PostgreSQL MCP server (`postgres` toolset) or `psql` to inspect schema state and verify queries:
- **Inspect table schemas and constraints**:
  - Check auto-migrated column types and nullability against Go model definitions in `../../../api/models`.
  - Validate foreign keys (`pokemon_species_id`, `move_type_id`).
- **Verify index creation**:
  - Confirm the `NULLS NOT DISTINCT` unique index on `evolution_details` exists when connected to PostgreSQL 15+.
- **Query verification**:
  - Test complex joins or aggregation queries with read-only SQL before embedding them in GORM queries.

### 8. Error Handling in Handlers

- Return structured JSON error payloads: `gin.H{"error": "Readable message"}`.
- Use appropriate HTTP status codes: `400` for validation, `404` for not found, `500` for server errors.
- Wrap errors with context using `fmt.Errorf("operation: %w", err)`.

### 9. Testing Patterns

Tests use `github.com/stretchr/testify/suite` with real database connections (no mocking).

```go
type ExampleTestSuite struct {
	suite.Suite
	router *gin.Engine
}

func (s *ExampleTestSuite) SetupTest() {
	models.ConnectDatabase()
	s.router = routes.SetupRouter(models.DB)
}

func TestExampleSuite(t *testing.T) {
	suite.Run(t, new(ExampleTestSuite))
}
```

**Running tests:**
- Tests require a reachable PostgreSQL 15+ database.
- Use `scripts/test-db.sh test` from the repo root to start a seeded test DB and run tests.
- Or point `api/.env` at your own database and run `cd api && go test -v ./...`.

**When writing new tests:**
- Place test files in `api/controllers_test/` (external test package).
- Use `httptest.NewRecorder()` and `http.NewRequest` to simulate requests.
- Test against the real Gin router with real database data.

### 10. Environment Configuration

- `models.ConnectDatabase()` loads `.env` from `.env`, `../.env`, and `../../.env` (in order).
- Environment variables: `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_PORT` (optional, defaults to `5432`).
- In Kubernetes, these are injected via ConfigMap (`api-config`) and Secret (`api-secret`).

---

## Key Constraints

- **No global DB in controllers** — always use constructor-injected `*gorm.DB`.
- **No direct `models.DB` access in handler methods** — use `h.db`.
- **Do not hand-edit `../../../api/docs`** — regenerate with `swag init`.
- **Evolution tables require the refresh job** — `ConnectDatabase()` does not create them.
- **PostgreSQL 15+ is required** — evolution details use `NULLS NOT DISTINCT`.
- **Base path is `/api/v1`** — all routes are registered under this group.
